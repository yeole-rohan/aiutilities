What Makes a Great README

1

Clear one-liner description

The first sentence should tell a developer what the project does, for whom, and why — in under 25 words. If they can't understand it immediately, they'll move on.

2

Working installation steps

A README that can't be followed to a working install in under 5 minutes will frustrate contributors. Test your own install steps. Make the prerequisites explicit.

3

Code examples

Show, don't tell. A 5-line code example is worth a paragraph of description. Show the most common use case — the 80% case, not the edge case.
