What Good Test Coverage Looks Like

✅

Happy path

The ideal flow — everything works as expected with valid inputs. This is where most teams start, but it's not where most bugs hide.

⚠️

Edge cases

Boundary values (min/max), empty inputs, very long strings, zero values, special characters — the unusual-but-valid inputs that expose hidden assumptions.

❌

Negative tests

Invalid inputs, missing required fields, wrong data types — tests that verify the system fails gracefully and shows helpful error messages rather than crashing.

🔒

Security tests

SQL injection, XSS payloads in form fields, unauthorised access attempts — basic security test cases that catch the most common vulnerabilities before they reach production.

Frequently Asked Questions

Can I use Gherkin format for Cucumber or Behave?
Yes — select "Gherkin / BDD (Given/When/Then)" format and the output will be in Feature/Scenario/Given/When/Then format compatible with Cucumber, Behave, SpecFlow, and other BDD frameworks. You'll still need to implement the step definitions.
Should I use this for manual or automated testing?
Both. The plain English and table formats work for manual QA test plans. The Gherkin format is for BDD automation. For traditional unit tests, describe the specific function in the feature field and select "Unit Tests" — the output gives you a test plan you can then implement in Jest, pytest, JUnit, or your preferred framework.
