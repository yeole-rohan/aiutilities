Common JWT Claims

    

      
ClaimMeaning

      
        
subSubject — who the token is about (usually user ID)

        
issIssuer — who created and signed the token

        
audAudience — intended recipients of the token

        
expExpiry — Unix timestamp when token expires

        
iatIssued At — Unix timestamp when token was issued

Frequently Asked Questions

    

      

        Is it safe to paste a JWT into this tool? ▼
        
Yes — the tool runs entirely in your browser. The token is never sent to a server. That said, avoid pasting live production tokens for sensitive services.

      

      

        Can this tool verify the signature? ▼
        
No — signature verification requires the secret key or public key. This tool only decodes (base64url-decodes) the header and payload; it does not validate the signature.

      

      

        What is a JWT used for? ▼
        
JWTs are used for authentication and authorisation. A server issues a signed token; the client sends it with every request; the server verifies the signature to trust the claims inside.

      

      

        Why does every JWT start with eyJ? ▼
        
The header is a Base64url-encoded JSON object. {"alg":"HS256","typ":"JWT"} always encodes to a string starting with eyJ.
